# LOCKD production-readiness audit

Audit date: 2026-10-28. The production URL, latest Vercel deployment and connected Supabase project were previously rechecked. This audit records observed behavior only; it does not certify legal compliance.

## Status key

- **Implemented, locally checked**: code exists and repository-level checks passed; external production behavior may still be unverified.
- **Partial**: a limited safe foundation exists, but it does not complete the customer or operator workflow.
- **Blocked by dependency**: code depends on a Supabase project, provider credentials, verified records, or approval that is not visible in this checkout.
- **Not implemented**: no production-capable code was found.

## Requirements and evidence

### Latest implementation update — 2026-10-28

- Added a dedicated room search at `rooms.html` with location, dates, adults/children, room quantity, property type and amenity filters. Search calls the approved-listing API and existing date-calendar RPC. It opens matching listing details and preserves search state. This is discovery plus a read-only check; it does not create a reservation.
- Added owner-entered room details to listing pages and only calculate a stay subtotal when `price_basis` explicitly defines `per_room_per_night` or `per_property_per_night`.
- Removed customer-facing price research, its public API/static snapshot, and the diagnostic photo-identification copy. Photos remain editorial category imagery; they are not represented as owner inventory.
- Added `20261028_0003_lockd_private_research.sql` to remove anonymous read access to existing research records. It still must be applied to the connected Supabase project because this environment has no Supabase CLI login and local browser access is disabled.
- Added an authenticated owner listing wizard in `owners.html` and `owners.js`: email/password access, confirmed-email gating, supported category-specific fields, browser-local recovery, account drafts, image preview/order/upload, KES rates, date availability, listing preview, publication, and owner pause/resume/archive controls. The API verifies user tokens and calls permission-checked SQL functions; no service-role key is used.
- Added `20261028_0004_lockd_owner_publishing.sql` with owner RPCs, direct publication after validation, date availability, and owner-folder-scoped image uploads. The migration has **not** been applied to live Supabase yet; owner database writes remain unavailable in production until it is.
- Tightened migration 0004 during this review: listing photos now use a private bucket, and the owner/public APIs request one-hour signed URLs under owner or published-listing access rules. The migration is still pending and has not been database-validated.
- Owner-created listings require owner confirmation before a booking. Publication does not create a reservation or payment; checkout and payouts remain disabled.
- Added Cars & Mobility to the shared catalogue, homepage and main navigation, category filters, global search, vehicle-specific owner form, and listing detail fields. The supplied vehicle photos appear in a clearly editorial section; they have no invented owner, rate, availability, or booking action.
- Added vehicle filters for class, transmission, fuel/powertrain, seats, minimum driver age and service mode. Date search still checks the existing calendar RPC and is read-only.
- Added a unified text-search path through `GET /api/listings`. Migration 0005 adds weighted PostgreSQL full-text ranking, typo-tolerant title/model matches, indexed search and accurate filtered counts. Until it is applied, the handler falls back to validated substring search.
- Added `20261028_0005_lockd_unified_search.sql`. It has **not** been applied or validated against the live database.
- Added `.vercelignore` so repository Markdown and SQL setup/audit documents are not deployed as public website files.

## What this checkout can safely claim

- The connected Supabase URL and publishable key are configured for Vercel Production. The latest Production deployment from the connected GitHub `main` branch is Ready at `https://lockd2.vercel.app`.
- Live `GET /api/listings` returns `200` with an empty list. Live `POST /api/availability` returns `200` after calling the Supabase RPC; the probe used a nonexistent UUID and is not evidence of a real listing's availability. There are no rental records or calendars yet.
- The connected Supabase project is healthy. Migration 0007 was applied and recorded as `20261028210034`. Its three account tables, RLS policies, signup trigger, and save RPC were verified. Current table counts are zero; no live auth account has tested persistence. Earlier SQL Editor changes may not appear in migration history. There are no actual rental records or calendars yet.
- Migration 0004 is code-reviewed locally but has not been applied or verified against the live Supabase schema. The new owner flow cannot be claimed as production-functional until it is applied and tested with a verified account and uploaded photo.
- Migration 0005 is code-reviewed locally but has not been applied or database-validated. Ranked and typo-tolerant search depends on that migration; substring search remains as the safe fallback.
- Migration 0006 (`supabase/migrations/20261028_0006_lockd_discovery_feed.sql`) is code-reviewed locally but has not been applied or database-validated. Current-location distance search and owner map-pin saving depend on it. Manual locality search and published-listing browsing do not require the new location RPC; publication ordering falls back to creation time while `published_at` is absent.
- The homepage discovery feed and optional owner map-pin form are implemented in this checkout. The nearby endpoint returns only approved public listing fields and approximate integer distances; its database function excludes listings without an owner-provided approximate map pin. The feature is not production-verified, and the catalogue currently has no real inventory to validate against.
- `api/supabase-config.js` accepts the Supabase project URL plus either `SUPABASE_PUBLISHABLE_KEY`/`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` or the legacy anon-key names. New publishable keys use only the `apikey` header; elevated secret and service-role keys are rejected.
- Migration 0007 is recorded in Supabase's migration history. Earlier SQL Editor changes may not be; establish and verify a baseline before relying on CLI migration ordering.
- It can ask the database whether configured date capacity appears available. This is a read-only check; it creates no hold, request or reservation.
- The package builder is a browser-local draft. It does not submit a booking, guarantee availability or calculate fees/taxes or a combined checkout total.
- The customer account experience shares the existing Supabase Auth identity and owner session in code. Migration 0007 is live with user-scoped RLS, but no real profile, saved-listing, or deletion-request operation has been tested through a signed-in account.
- Email/password, recovery and Google PKCE OAuth handlers are implemented. Email delivery and Google OAuth have not been verified against live provider settings. Apple sign-in is intentionally omitted from LOCKD.
- The customer account UI and shared persistent-favourite wiring are implemented locally. The in-app browser connection reports that browser access is disabled in Work settings, so this turn could not complete visual/browser interaction QA; a local HTTP request to `/account.html` returned `200`.
- Saved rental controls are wired in the deployed catalogue, room, technology, nearby-discovery and rental-detail views. The required database schema is live; two-account RLS validation remains outstanding.
- Booking history is not available: no customer reservation flow exists, and no completed bookings are shown.
- `account.html`, `auth-callback.html`, and the provisional `privacy.html` are marked noindex; the sitemap intentionally excludes them.
- No completed payment, refund, payout, booking acceptance, legal identity verification or legal compliance is established by this code. The owner portal requires email confirmation, but email delivery and owner identity checks remain unverified.
- Market research is no longer displayed on the customer-facing site. Migration 0003 must be applied to close anonymous access to previously seeded research rows. The current production catalog contains no owner listings.

## Release decision

**Not production-ready for marketplace transactions.** Keep booking and payment calls disabled until the lifecycle, concurrency controls, permissions, provider callbacks, reconciliation, notifications, privacy/legal work and end-to-end acceptance scenarios above are implemented and pass in the intended production configuration. A successful page load or Vercel deploy is not sufficient evidence.
