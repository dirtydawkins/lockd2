## What this checkout can safely claim

- The connected Supabase URL and publishable key are configured for Vercel Production. The latest deployment for commit `10a6855` is Ready at `https://lockd2.vercel.app`.
- Live `GET /api/listings` returns `200` with an empty list. Live `POST /api/availability` returns `200` after calling the Supabase RPC; the probe used a nonexistent UUID and is not evidence of a real listing's availability. There are no rental records or calendars yet.
- The connected Supabase project is healthy. Both migrations were applied in its SQL Editor; the tables, availability functions, 39 published benchmark references and public grants were verified. Anonymous users can read listing IDs and cannot read `owner_id`. There are no actual rental records or calendars yet.
- `api/supabase-config.js` accepts the Supabase project URL plus either `SUPABASE_PUBLISHABLE_KEY`/`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` or the legacy anon-key names. New publishable keys use only the `apikey` header; elevated secret and service-role keys are rejected.
- Vercel's 6-hour Observability card still showed a 100% error rate during this audit, while the direct API probes above succeeded after the new deployment. Recheck logs and metrics as the window updates.
- The migration SQL was applied manually and may not be recorded in the Supabase CLI migration ledger; use a tracked baseline for future schema changes.
- It can ask the database whether configured date capacity appears available. This is a read-only check; it creates no hold, request or reservation.
- The package builder is a browser-local draft. It does not submit a booking, guarantee availability or calculate fees/taxes or a combined checkout total.
- No completed payment, refund, payout, email, identity verification, owner approval or legal compliance is established by this code.

## Release decision

**Not production-ready for marketplace transactions.** Keep booking and payment calls disabled until the lifecycle, concurrency controls, permissions, provider callbacks, reconciliation, notifications, privacy/legal work and end-to-end acceptance scenarios above are implemented and pass in the intended production configuration. A successful page load or Vercel deploy is not sufficient evidence.
